This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The public demo of NotORM at demo.notorm.com. NotORM itself is the Composer dependency `vrana/notorm` (its source is in the sibling `../../notorm` checkout); this repo has only the demo. Setup and deployment are in `README.md`: `composer install`, `config.php` from `config.example.php` (gitignored, the repo is public), `php setup.php name` to recreate the tables of a database from `config.php` (`sql/$driver.sql` by the PDO driver, then the rows from `sql/data.sql`; `setup.php` handles IDENTITY_INSERT in MS SQL and one row per INSERT, no DROP TABLE IF EXISTS and moving the identities in Oracle 21), document root `www/`. Locally `php -S 127.0.0.1:8000 -t www` with the database `notorm_demo` in MySQL, MariaDB (port 3307) and PostgreSQL 18 (`ODBC`/`ODBC`), MS SQL (`ODBC`/`ODBC`, PHP 8.5 only) and the Oracle user `notorm_demo` in XEPDB1 (PHP 8.5 only), and an SQLite file in `var/` (gitignored, also the `File` and `IncludeFile` caches, never the shared temp directory). Keep the schemas in sync. PDO returns lower case column names (`PDO::ATTR_CASE`) because of Oracle.

Each table in `sql/data.sql` has its own hundred of ids (author 1xx, tag 2xx, application 3xx, category 4xx), so a wrong table in a query finds nothing instead of an unrelated row. Keep it so when adding rows.

Code follows NotORM's idiom: `<?php declare(strict_types=1);`, tabs, `function` without visibility, native types, PHP 8.0 as the minimum (no `never`, `readonly`, enums; no mbstring, which isn't loaded in the local PHP 8.0). Check changes with PHP 8.0 (`C:\Program Files\PHP80\php.exe`) and the latest PHP; before 8.1, PDO MySQL returns numbers as strings, so cast them where a native type is required.

## How it works

- `www/*.php` are the pages, one file per page with the id in the query string (`application.php?id=301`). Each requires `include/bootstrap.inc.php`, handles its POST, then calls `page_header()` and `page_footer()` from `include/layout.inc.php`. The query log quotes the pages and links to them on GitHub, so keep them short and readable and keep the NotORM calls in them, not in helpers.
- `include/QueryLog.php` is set as NotORM's `debug` and `debugTimer` callbacks. For each query it finds the first stack frame outside NotORM and `include/` and shows the PHP statement around that line, found by `PhpToken` (split at `;`, `{`, `}` and PHP tags). Results are lazy, so this is where the rows were first read, e.g. the `foreach`, not where the query was built. When one line has several statements, the ones with `->` win.
- Each query is shown where its data start: `bootstrap.inc.php` starts an output buffer, `QueryLog::start()` remembers its length, and `page_footer()` lets `QueryLog::mark()` put `<template data-query="N">` there, moved before `<` when inside a tag. The queries run before the page printed anything go before the `<h1>`, the writes of `demo_write()` (`QueryLog::notice()`) before the notice. `<template>` is allowed even in `<table>` and `<select>`, so the browser keeps it in place. `demo.js` finds the nearest place which may contain a link or a query (the first cell of the next row, before a `<select>` with its label, before an `<a>`) and puts a link `#N` there; on wide screens the cards are in a `.queries` group floated right before the top-level block of `<main>`, hovering or clicking the link highlights the card; on narrow ones the card itself is there and the links are hidden. Cards have `width: 0; min-width: 100%` so that they don't widen table cells and grid columns. Run a query where its result is printed if it should be shown there, e.g. `<?=$count = $applications->count("*")?>`. Without JS, the cards stay listed after `<main>`.
- Writes go through `demo_write()` in `include/functions.inc.php`: `BEGIN`, the closure with the NotORM writes returning the message and the URL of the result, then `COMMIT` with `read_write` in `config.php` (constant `READ_WRITE`), `ROLLBACK` otherwise or after an error. PDO errors (e.g. deleting an author who has applications) become the notice. After a commit, the rows loaded by the page may be gone or stale, so it stores the notice and `QueryLog::export()` in the session and redirects with 303; `bootstrap.inc.php` sets `$notice` and `QueryLog::import()`s the writes, which go before the notice. Without a commit, the same response shows the notice, and the rows loaded before the writes keep their values (`Row::update()` doesn't change them). Every page passes `$notice` to `page_header()`, also the targets of a delete (`index.php`, `authors.php`). Keep `read_write` false on demo.notorm.com.
- The database is the visitor's choice too: `databases` in `config.php` (constant `DATABASES`, `db_choice()` reads the `db` cookie, set by the same form as the cache). The SQL is highlighted in the dialect of the PDO driver (`sql_language()`, `build-jush.php` builds `jush-sql`, `jush-sqlite`, `jush-pgsql`, `jush-mssql` and `jush-oracle`). SQLite gets `PRAGMA foreign_keys = ON` in `bootstrap.inc.php`. `CacheByDatabase` prefixes the keys of the chosen cache with the database name: Discovery caches PostgreSQL's sequence, and MS SQL's `lastInsertId()` returns "" with it. Qualify the columns of ORDER BY in queries with a join (`application.id`), Oracle reports a bare `id` as ambiguous.
- The cache is the visitor's choice: the `<select>` in `page_header()` posts `cache` on change (`demo.js`), `bootstrap.inc.php` stores it in a cookie and redirects back with 303 before the page sees the POST, so it never reaches the pages' `if ($_POST)` writes. With Session chosen, the switch also offers `CLEAR!` (`clear`), which empties `$_SESSION["NotORM"]` and keeps the cookie. `config.php` lists the allowed `NotORM\Cache` classes with their constructor arguments in `caches` (the first one is the default; a `Closure` instead of the arguments is called with the PDO connection only for the chosen cache, e.g. `Database` or a Memcached connection), `""` is off (stored as `off` in the cookie, which can't be empty), the constant `CACHES` has their short names, `cache_choice()` reads the cookie and the same cache serves the columns and Discovery's foreign keys.
- CSRF protection is central in `include/bootstrap.inc.php`: a POST with `Sec-Fetch-Site` other than `same-origin` gets 403. A missing header is allowed (curl, old browsers), because a CSRF victim's browser always sends it.
- The structure is `NotORM\Structure\Discovery` with `%s_id`, so `$application->maintainer` finds the table `author` from the foreign key. Two foreign keys of `application` point to `author`: `$author->application()` uses `author_id`, the conventional one by `%s_id` (NotORM 2.1+), and `->via("maintainer_id")` the other one.
- `build-jush.php` (run by Composer) concatenates only the JUSH modules in its `$modules` into `www/static/jush/jush.js`; add a module there when highlighting another language (e.g. `jush-pgsql` for PostgreSQL).
